# Границы интеграции локальной редактуры

Статус: проверка действующих точек входа, не выполненная миграция.
Основной и установленный `SKILL.md` остаются 3.23.0.

## Что мешает просто добавить абзац

1. Основной `SKILL.md` одновременно запрещает правку зелёного абзаца и советует
   профилактические контрастные замены в нём (шаг 1). Шаг 3 снова запрещает
   трогать зелёное. В локальном режиме таких замен нет.
2. По умолчанию запускается полная правка с каталогом; три маркера требуют
   переписывания абзаца целиком. Новый режим выбирает объём по проблеме читателя.
3. `commands/humanize.md` самостоятельно требует контрастного вычитания и
   quad-pass. Изменить только скилл недостаточно: команда вернёт прежнее поведение.
4. Каталог содержит пороги и предписания, которые нельзя автоматически переносить
   в локальную редактуру. Одновременная загрузка старой процедуры и нового режима
   создаст конкурирующие инструкции вместо чёткой маршрутизации.
5. `edit-log.md` сейчас пустой, но его приоритеты подчинены HARD BANS. В новой
   схеме пожелания к стилю не должны отменять сохранение смысла.
6. `scripts/lint_skill.py` запрещает тире в собственной прозе и одобренных примерах.
   Такой тест проверяет прежнюю стилевую политику, а не сохранность текста.
7. `eval/humanize_pass.py` загружает только основной `SKILL.md`. Для вынесенного
   режима ему потребуется явный состав промпта; иначе тест и реальная работа
   будут проверять разные инструкции.

## Предлагаемая граница миграции

Входной скилл выбирает одну процедуру: локальная правка по умолчанию либо аудит
без переписывания по запросу. Не запускать поверх локальной правки старые пять
шагов. Точечная просьба дополнительно ограничивает допустимые изменения.

Каталог сохраняется как справочник возможных проблем для аудита, а не обязательный
список замен для каждого текста. Сканер сохраняется как измеритель собственных
сигналов. Его балл не означает качество редактуры или вероятность ИИ; без запуска
сканера число не придумывается. Рабочую интеграцию проверять с реальными командами,
маршрутами загрузки и всеми действительно прочитанными файлами.

## Перед переключением

- [x] Пройден зафиксированный критерий `SCOPE_CHECK.md` (0/30 у обоих кандидатов;
      дополнительный выигрыш уточнения не доказан).
- [ ] Изолирован маршрут локальной правки и обновлена команда humanize.
- [ ] Проверен аудит: не переписывает текст, не выдумывает балл сканера.
- [ ] Полный пакет с выбранным маршрутом не ухудшил результаты 13 случаев
      предыдущего эксперимента; однофайловый тест не выдаётся за интеграционный.
- [ ] Проверены ссылка на сканер, загрузка ссылочных файлов и упаковка.
- [ ] Установка и публикация явно отделены от локального кандидата.

Этот документ фиксирует необходимый объём совместимой интеграции. Он не является
доказательством, что маршрутизация уже реализована или проверена моделью.
