# Дистрибуция humanizer-ru для Codex CLI (v3.5.x) — дизайн

Дата: 2026-06-12. Статус: утверждён Ильёй (вариант «A: только README», без Codex-смоука).

## Контекст

v3.5 собрана и проверена (линт + тесты зелёные), но не закоммичена. Codex CLI поддерживает
тот же формат Agent Skills: папка со `SKILL.md` (frontmatter `name` + `description`),
установка в `~/.codex/skills/` или `.codex/skills/`, вызов через `$имя` или автотриггер
по description. Наш `SKILL.md` платформо-нейтрален: чистый промпт, скрипты (`scripts/`,
`eval/`) — инструменты разработки, скилл их не вызывает. Фоллбэк не нужен.

Находки аудита установки (2026-06-12):

- frontmatter `description` = 1157 символов при лимите Claude Code 1024 — риск, что
  скилл не регистрируется или описание обрезается, ломая автотриггеринг;
- локальная копия `~/.claude/skills/humanizer-ru/` у Ильи — устаревшая v3.0,
  свежий установочный путь никем не проходился;
- Codex CLI на машине не установлен — живой Codex-тест сознательно вне скоупа.

## Цель

Пользователь Codex CLI может установить скилл по инструкции из README. Автотриггеринг
не страдает от переполненного description ни на одной платформе.

## Изменения

### 1. Порядок коммитов

1. Закоммитить v3.5 как есть (отдельный коммит в `main`, по конвенции прошлых релизов).
2. Эта доработка — следующим коммитом в `main`, с патч-бампом версии до `3.5.1`
   в `.claude-plugin/plugin.json` (frontmatter скилла меняется — пользователи должны
   увидеть обновление).

### 2. README.md и README.en.md — секция установки для Codex

В существующий раздел «Установка» добавить пункт «4. Codex CLI (OpenAI)»:

```bash
git clone --depth 1 https://github.com/ilyautov/humanizer-ru
mkdir -p ~/.codex/skills
cp -r humanizer-ru/skills/humanizer-ru ~/.codex/skills/
```

Плюс: альтернатива через `skill-installer` (путь `ilyautov/humanizer-ru/skills/humanizer-ru`),
строка про перезапуск Codex и вызов через `$humanizer-ru` или автотриггер.
Формулировка честная: «формат Agent Skills общий», без клейма «протестировано в Codex».
README.en.md — та же секция по-английски.

### 3. Ужать frontmatter description до ≤1024 символов

В обеих копиях (`SKILL.md` корня и `skills/humanizer-ru/SKILL.md`, байт-в-байт одинаково).
Сократить за счёт повторов и второстепенных триггер-фраз. Сохранить обязательно:
назначение (очеловечивание русского AI-текста), самые частотные триггеры («очеловечить»,
«убрать следы нейросети», «сделать текст живым», «убрать канцелярит», «перепиши как
человек», «humanize»), ограничение «ТОЛЬКО русский, для английского — оригинальный
humanizer», список «НЕ используй для: перевод, написание с нуля, грамматика, код».

### 4. Гард в `scripts/lint_skill.py`

Новая проверка: длина значения `description` во frontmatter ≤ 1024 символов.
Падение линта с понятным сообщением при превышении.

### 5. Верификация установки (Claude Code, локально)

После ужатия description: обновить локальную копию `~/.claude/skills/humanizer-ru/`
до v3.5 (тем же путём, что у пользователей: `npx skills add` или ручная копия) и
проверить в свежей сессии, что скилл виден и описание не обрезано.

## Вне скоупа

- install.sh, заявки в каталоги (awesome-codex-skills, agensi), eval на GPT-моделях.
- Живой смоук в Codex CLI (нет Codex на машине; решение Ильи — выпускать без него).
- Любые правки тела скилла (паттерны, баны, процесс).
- Чистка веток `claude/loving-lederberg` (prunable worktree) и `origin/v3-research-upgrade`
  (перекрыта v3.1-v3.4) — ждёт отдельного «да» Ильи, удаление remote-ветки необратимо.

## Проверка готовности

- `.venv/bin/python scripts/lint_skill.py` зелёный (включая новый гард длины).
- `.venv/bin/python scripts/test_markers.py` зелёный.
- `awk '/^description:/ {print length($0)-13}' SKILL.md` ≤ 1024 (обе копии).
- README-секция читается, команды копируются и выполняются без правок.
- Свежеустановленная копия в `~/.claude/skills/` = v3.5, триггерится.
